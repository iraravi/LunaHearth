# On-device AI reliability audit — 2026-09-28

## Scope and data boundaries
Reviewed all nine FoundationModels adapters and their main consumers: shopping ideas, pantry templates, meal ideas, receipt name decoding, pantry photo recognition, pantry categories, duplicate comparisons, Today briefs and assigned-shopping briefs. Also reviewed rule-based quick-add, publisher switches, input/output rules, cancellation, review/save boundaries and offline fallbacks.

Affected entities are shopping proposals, pantry labels/categories, meal proposals, receipt line-name proposals and read-only summaries. Existing user confirmation before important writes remains required. No SwiftData or CloudKit schema changes, migrations or network integrations. Model content stays on device. Local diagnostic metadata stores only one latest result per feature in UserDefaults; users can clear it in AI Status. No raw error context is retained.

## Confirmed findings and changes
| Finding | Change | Limit |
|---|---|---|
| Failed typed shopping plans could return unrelated purchase history or generic staples | Typed-plan failures now return no ingredient proposals; explicit status; history omitted from model context | Does not prove which path produced the reported lentils |
| Most model errors collapsed into generic failure | Typed error classification and private last-result diagnostics across all adapters | Unknown errors remain explicitly unidentified; no historic errors can be recovered |
| Long category/comparison inputs sent in one request | Small independent batches with validated original index mapping; total item-text budget for shopping briefs | Extra sequential calls may add latency; no token guarantee |
| Meal output allowed blank/repeated ingredients and unconstrained minutes | Generation guides, deterministic label checks and alias deduplication | Structural validity cannot establish dish completeness or allergy safety |
| Pantry edits could receive a stale answer | Invalidate generation when request changes; snapshot checks | Live shared state can still change after a preview; save-time checks remain necessary |
| Meal/assigned-shopping results lacked full context checks | Reject responses after household/input changes or cancellation | Does not cancel completed saved records |
| Today and assigned-shopping AI buttons missed availability gates | Apply existing capability and publisher checks; retain manual summaries | Publisher changes do not guarantee immediate cancellation of an in-flight model request |

## Adapter review matrix
| Adapter | Offline / unavailable behavior | Validation / cancellation |
|---|---|---|
| Shopping ideas | Labelled built-in ideas only for blank plan; no pretend answer to typed plan | Name/quantity limits, pending/pantry exclusions, user review, cancellation |
| Pantry templates | Existing built-in templates remain | Names filtered/deduped, existing stock excluded, edited requests invalidated |
| Meals | Labelled built-in suggestions; extra notes explicitly not applied | Bounded pantry/context, 1–15 ingredients, 1–180 estimated minutes, no steps, user review |
| Receipt names | Original OCR labels preserved; manual editing | Batches of 12, original line identity/index checks, reviewed rename only |
| Pantry photo | Vision OCR label reading when image model unavailable | Image size/decode limits, capability guard, name validation, review before stock writes |
| Categories | Deterministic category rules remain | Batches of 10, allowed category values and index checks; temporary hints |
| Duplicate comparison | Deterministic aliases/manual review remain | Batches of 12, bounded validated indices; no automatic merge/delete |
| Today brief | Deterministic saved-record summary | Bounded supplied facts, cancellation, read-only AI-labelled output |
| Assigned-shopping brief | Deterministic item summary | Bounded items, cancellation and household/item snapshot checks, read-only output |

## Remaining evidence needed
The reported chicken-briyani/lentil answer has not been reproduced with the physical Apple model. Previous code did not retain failure categories, so its exact historical cause is unknown. The fallback bug is confirmed independently. A correctly shaped generated response can still omit chicken or add an unrelated ingredient; stronger prompts are guidance, not proof.

Simulator tests deliberately bypass actual model generation. They verify application behavior, not model quality, model memory use, battery drain or real-device latency. Test on a capable physical device with synthetic inputs for chicken biryani/briyani, vegetarian exclusions, regional aliases, unsupported language, long lists and cancellation. Check AI Status after failures; if it says generation completed, inspect the proposal itself rather than treating it as a technical error. Do not use real household content in shared logs.

This audit adds no cloud AI, cooking directions, allergy guarantees or food-safety certification. Changes are not yet deployed to TestFlight.
