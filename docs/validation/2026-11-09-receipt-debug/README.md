# Internal receipt debugging

More → AI Status → Receipt debug · Developer is compiled only with RECEIPT_DEBUG. Debug and the new Internal configuration define it. The normal Release configuration does not. Use the LunaHearthInternal scheme to archive a developer TestFlight build, distribute with TestFlight Internal Only, and assign only to intended developer testers. A build configuration is not user authentication: every recipient of an internal build can access its lab. Do not submit that archive for public distribution; public archives use LunaHearth / Release.

The lab accepts camera pages or up to four selected photos, runs the same VisionReceiptScanner → OnDeviceReceiptExtractionService pipeline, and shows numbered OCR text, structured generated item fields, source-validation failure reason, pipeline fallback status, final item amounts/review markers, and proposed store/date/total. It does not expand abbreviations or change the extraction rules. An accepted structure is not a promise of monetary accuracy; review flags show failed reconciliation. A model failure may have no generated output; OCR remains visible if inference fails or times out.

Affected data: transient ReceiptScan and ReceiptItemEvidence only. No household records are read or written; no expense, inventory, image or debug-report persistence. The report is held in screen state and cleared on leaving, explicit clear, or starting another scan. Sharing requires the tester to explicitly invoke Share debug text; reports contain private OCR/payment/member information and should be reviewed before sharing. No automatic transmission, SDK, CloudKit change or new permission. PhotosPicker avoids broad library access; the existing camera permission is just-in-time.

Public Release excludes the lab, report builder, ReceiptScan diagnostic field and structured-output capture branches using compile-time conditions. Normal result-category diagnostics remain unchanged. Tests cover multiline evidence rejection reporting and full report contents; existing scan-session tests cover cancellation, timeout and stale completions. Actual device model output must still be tested in the internal build.
