# ADR 038 — Connected family week

User approved a family week planner connecting appointments, tasks, meals and shopping, with reviewed on-device suggestions. Calendar and Today link to Family week; no root tab is added. The iPad uses horizontally scrolling day columns, with explicit dates; compact and accessibility sizes show a selected day with labeled date buttons and optional horizontal swipe. Resizing does not reset selected dates or filters. Person filters include that person's and unassigned household appointments/tasks; meals remain household-wide. Undated tasks, overdue tasks outside the selected week and undated shopping remain in existing lists/Today. Personal Apple calendars are not included in weekly scheduling and the UI states this.

The view reads the existing FamilyEvent, HouseholdTask, MealPlanEntry and GroceryItem records. Each appointment/task/meal opens its original detail screen. Weekly shopping reuses the existing measured-pantry review and duplicate protections. No duplicate calendar records, new model/schema, automatic stock changes, permission prompts or new sync transport.

Plan our week reuses the on-device meal service and labelled built-in fallback. Only pantry names, selected cuisine and explicit context reach the service; appointment text and member identity do not. A deterministic rule merges appointment intervals between 4 and 8 PM. At least an hour of occupied time causes quicker candidate recipes to rank first. Other evenings retain pantry-based ranking. Build 45 defaults to breakfast, lunch and dinner, with independent meal-type toggles. At least one type must be selected to generate; changing selection invalidates the draft. The planner preserves existing occupied slots, allows swapping and deselection, and labels repeats/unknown quantities. All-day/overnight household appointments participate by their intervals. This is a bounded heuristic, not a guarantee of recipe duration or personal availability.

Optional dinner prep reminders start OFF. Breakfast and lunch do not receive evening prep tasks. Proposals use a free 30-minute window between 4 and 7 PM, scanning back from 6:30 PM in 15-minute steps and avoiding all household appointments. Proposed times are visible before saving. Past times and days with no window get no reminder. These are unassigned household tasks linked by existing mealID; this does not claim a recipe takes 30 minutes or create an alarm automatically. Existing notification preferences remain unchanged. Users can assign/edit tasks after saving. Later appointment changes do not automatically reschedule saved meals or prep tasks; this is a reviewed planning action, not a background assistant.

One local transaction saves selected meals and selected optional prep tasks. The repository validates household, meal slots, input fields and fresh prep availability before any mutation; a changed schedule rejects the review for regeneration. Repeat save cannot duplicate a meal/task. Existing write-access guards, tombstones and optional private/shared CloudKit apply. No remote service is needed for core operation and no live data is seeded or deleted for tests.

Validation covers merged scheduling intervals, overnight events, midnight boundaries, DST civil days, blocked/no-window cases, atomic persistence, stale appointment rejection, repeat-save prevention and backup roundtrip. UI automation exercises navigation, person filtering, reviewed dinner/prep creation and shopping review using in-memory fixtures and the existing model fallback.
