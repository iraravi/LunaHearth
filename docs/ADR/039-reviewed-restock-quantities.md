# ADR 039 — Reviewed restock quantity arithmetic

User requested a deep functional check of shopping, pantry counts, receipts, expense reports and meal ingredient shopping. The audit found restock actions cleared Low stock while retaining even compatible measured quantities. New restocks now add compatible mass/volume/piece quantities and matching package counts (e.g. cartons to cartons). Domain rules use Decimal with bounded three-decimal results, preserve existing units, and never convert mass to volume or infer container size. Unknown balances/units remain unchanged, with an explanation in purchase and receipt review. Grocery completion and receipt replay guards prevent applying the same recorded stock action twice. No historical quantities are retroactively rewritten.

Affected existing entities: InventoryItem quantityText/modifiedAt, GroceryItem completion and purchaseDisposition, PurchaseEntry history and HouseholdExpense. There is no schema migration, new cloud transport, model inference, permission or network service. Local writes remain atomic and use existing private/shared sync. Simultaneous independent offline edits still use entity conflict resolution; this is not a distributed arithmetic ledger. Expiry stays unchanged for shopping restocks; receipts update it only if explicitly selected in review. Separate pack remains available for different expiry dates. Expired packs are excluded from restock matching: their amounts and dates stay untouched, while the new purchase creates a fresh pack or matches another current pack. The shopping review explains this; stale receipt selections of expired packs reject before any write.

Expense amount text now formats Swift Int values without a 32-bit printf conversion, preserving validated large totals across editing/export. Currency separation and refund arithmetic are unchanged.

Tests cover unit conversion, package equality, missing/unknown/incompatible quantities, bounds, repeat purchase/receipt, full shopping → pantry → receipt/expense → meal consumption → shopping ingredients, disk reopen and backup restore. Real household data is not used for test fixtures. Live cross-device conflict behavior and model/physical-camera accuracy remain separate checks.
